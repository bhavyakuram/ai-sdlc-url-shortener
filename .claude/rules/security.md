# Rule: Security

**Category:** Security · **Priority:** 3

## Zero-Regression Posture
No merge/generation wave may lower the security posture of in-scope
code versus its pre-run baseline. security-audit (STEP-6.2) diffs
findings against the baseline captured at PRE-WORK; any new
HIGH/CRITICAL finding is a BLOCKER regardless of the feature's own risk
level.

## Credential Hygiene
No secret, API key, token, or credential may ever appear in generated
source, generated tests, agent reports, or `_run-log.md`. The MCP hook
layer scrubs auth tokens from cached responses before they touch disk
(`pre-tool-use.py` / `post-tool-use.py`).

## Input Validation & Injection
Every externally-reachable input (path params, query params, request
bodies) generated by `generator` must be validated at the boundary.
SQL/NoSQL query construction must use parameterization — string-built
queries are a BLOCKER at static-analysis.

## Dependency Hygiene
`dependency-audit` (STEP-1) and `security-audit` (STEP-6.2) both check
new/changed dependencies against known-CVE databases for the active
stack (`pip-audit`/`bandit` for Python, `dependency-check` for Java).
